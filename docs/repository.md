# 滚动恢复点与仓库整理

从 1.1.0 开始，成功备份后默认保留最近两个成功恢复点和全部固定点。需要长期留存的点应先固定。失败、取消和未提交的备份不会淘汰已有可用点；保留点的 ID、描述文件字节、来源关系和固定状态保持不变。

新建仓库默认启用滚动保留。升级前的仓库不会因安装新版而立即淘汰旧点；须先固定需保留的点，再成功执行一次“验证并整理仓库”，随后进入默认滚动管理。

GUI 的“备份与恢复”页显示当前策略，并提供“验证并整理仓库”和“恢复中断的仓库切换”。Agent 使用 `repository.status`、`repository.compact`、`repository.recover`，参数为可选的 repository；与 GUI、自动备份共用一个写入队列。完整恢复、逐文件校验和迁移包导出继续使用原接口。

过期描述文件只在新的成功点提交后退役，审计保留最近 200 条描述文件哈希及累计计数。块数据不会逐块原地删除。存在已退役点时，默认每七天自动整理一次；也可手动提前整理。手动和定期整理占用同一维护队列，采集在整理结束后续行；大库的重建与全验证可能耗时较长，可在安全检查点取消。程序先在仓库旁构建独立新仓，逐个认证全部引用块、文件映射、媒体和配套文件，完整重建并哈希全部保留点的文件，再执行目录切换。新仓保留原块编号和恢复点身份；旧式外置块切片会转成独立数据块。

切换使用仓库外的操作锁和落盘日志。校验失败时不切换；未提交的切换在重启时回退，已提交的切换续用新仓。旧仓清理另有落盘回执，已验证并获准退役的清理可中断续接，待验收的旧仓继续保留。安全退出及任务取消均通过检查点处理。普通查询当前聊天不需要仓库锁；仓库验证、恢复、导出持有共享读取锁，整理和备份持有互斥锁。长时读取期间，备份可排队等待；可在任务中取消。

整理需暂时容纳一份新块数据库。冻结原件在同卷可复用不可变硬链接，但仍逐字节哈希；硬链接不构成跨设备独立备份。换电脑应复制完整仓库或完整迁移包，并在新目录进行默认的全验证恢复。

空间报告须区分编码数据量、数据库文件大小、逻辑文件总量和磁盘空闲空间变化。删除旧目录时不会修改共享文件属性，不跟随链接，不删除不认识的文件。原始源库、密钥、历史原件、现用状态、固定点及其依赖都不是临时缓存。

公开版本仅包含程序、源码和合成夹具验证。真实账号、文件清单和实恢回执保存在本机私有工作目录，不随公开发布上传。

导出旧恢复点时，点内原版程序保持原字节；当前程序与原版不同时，另附 recovery-tool，新建的恢复、阅读和 Agent 入口使用它。相同版本则复用原版，避免重复。复制时保留整个目录。
